1. Optimizar la imagen principal del home

La imagen grande que aparece al inicio debe pesar muy poco.

Qué debes hacer

Busca la imagen principal de la página. Probablemente está en alguna carpeta como:

/public/images/
/src/assets/
/assets/
/img/

o en el panel del constructor web si usaste Vercel, React, Next.js, Astro, WordPress, etc.

Debes crear 2 versiones:

hero-mobile.webp
hero-desktop.webp

Tamaño recomendado:

hero-mobile.webp   →  480 px a 768 px de ancho
hero-desktop.webp  →  1280 px a 1600 px de ancho

Peso recomendado:

hero-mobile.webp   →  máximo 150 KB a 250 KB
hero-desktop.webp  →  máximo 250 KB a 450 KB

No uses una imagen de 3000, 4000 o 5000 px para móvil.

2. Convertir imágenes a WebP o AVIF

Evita usar imágenes pesadas tipo:

.jpg grande
.png grande

Convierte la imagen principal a:

.webp

o mejor:

.avif

Mi recomendación práctica:

Usa WebP primero.

WebP es más compatible y suficiente para mejorar bastante.

Puedes usar herramientas como:

https://squoosh.app
https://tinypng.com
https://cloudconvert.com

Configuración recomendada en Squoosh:

Formato: WebP
Quality: 70% - 80%
Resize: Sí
Ancho móvil: 768 px
Ancho desktop: 1600 px máximo
3. No usar la misma imagen para móvil y escritorio

Este punto es clave.

Ahora probablemente la página está cargando en celular la misma imagen grande de escritorio. Eso mata el rendimiento móvil.

Debes cambiar el código de la imagen principal por una estructura tipo <picture>.

Ejemplo correcto
<picture>
  <source 
    srcset="/images/hero-mobile.webp" 
    media="(max-width: 768px)" 
    type="image/webp"
  >

  <source 
    srcset="/images/hero-desktop.webp" 
    media="(min-width: 769px)" 
    type="image/webp"
  >

  <img 
    src="/images/hero-desktop.webp"
    alt="Servicios industriales, automatización y soluciones petroleras"
    width="1600"
    height="900"
    fetchpriority="high"
    decoding="async"
  >
</picture>

Esto hace que:

Celular descargue hero-mobile.webp
PC descargue hero-desktop.webp
4. Agregar preload de la imagen principal

El navegador debe saber que la imagen principal es prioritaria.

En el <head> de la página agrega esto:

<link 
  rel="preload" 
  as="image" 
  href="/images/hero-mobile.webp" 
  media="(max-width: 768px)"
>

<link 
  rel="preload" 
  as="image" 
  href="/images/hero-desktop.webp" 
  media="(min-width: 769px)"
>

Esto ayuda directamente al LCP.

5. La imagen principal NO debe tener lazy loading

Esto es muy importante.

La imagen principal del primer pantallazo no debe cargar en modo lazy.

Incorrecto:

<img src="/images/hero.webp" loading="lazy">

Correcto:

<img 
  src="/images/hero.webp"
  fetchpriority="high"
  decoding="async"
>

Para el hero:

NO usar loading="lazy"
SÍ usar fetchpriority="high"
6. Colocar lazy loading en las imágenes secundarias

Todas las imágenes que estén más abajo en la página sí deben tener lazy loading.

Ejemplo:

<img 
  src="/images/servicio-scada.webp"
  alt="Servicio de integración SCADA"
  loading="lazy"
  decoding="async"
  width="800"
  height="500"
>

Esto evita que el navegador cargue imágenes que el usuario todavía no está viendo.

7. Definir width y height en todas las imágenes

Aunque tu CLS está en 0, igual es buena práctica.

Cada imagen debe tener tamaño definido:

<img 
  src="/images/servicio.webp"
  alt="Automatización industrial"
  width="800"
  height="500"
  loading="lazy"
  decoding="async"
>

Esto ayuda a que el navegador reserve el espacio antes de cargar la imagen.

8. Revisar si el hero tiene overlay, video o animaciones pesadas

Si el bloque principal tiene:

video de fondo
slider
animaciones grandes
efectos pesados
librerías de animación innecesarias
imagen con blur muy grande
background attachment fixed

debes quitarlos o simplificarlos.

Para el primer bloque de la página, lo ideal es:

Imagen comprimida
Texto HTML real encima
Botón simple
Sin video
Sin slider
Sin animación pesada

No uses carrusel en el primer bloque.

9. Evitar que el texto principal sea parte de la imagen

El texto que aparece en el hero debe ser texto real en HTML, no texto incrustado en una imagen.

Malo:

Una imagen completa que ya trae dentro el texto "Servicios Petroleros"

Bueno:

<section class="hero">
  <img src="/images/hero.webp" alt="Planta industrial">
  <h1>Servicios Industriales y Soluciones Petroleras</h1>
  <p>Automatización, SCADA, redes industriales y soporte técnico especializado.</p>
</section>

Esto mejora:

SEO
Accesibilidad
Velocidad
Lectura por Google
Calidad visual en móvil
10. Revisar CSS del fondo principal

Si la imagen principal está colocada como fondo CSS, por ejemplo:

.hero {
  background-image: url("/images/hero.jpg");
}

Google puede priorizarla peor que una imagen <img>.

Para LCP es mejor usar imagen real:

<picture>
  <source srcset="/images/hero-mobile.webp" media="(max-width: 768px)">
  <img src="/images/hero-desktop.webp" alt="Servicios industriales">
</picture>

Y encima colocar el texto con CSS.

11. Reducir JavaScript innecesario

Aunque tu TBT está bien, igual revisa si tienes librerías innecesarias.

Evita cargar:

sliders pesados
animaciones complejas
librerías que no usas
scripts externos innecesarios
chat widgets
mapas embebidos al inicio
videos de YouTube directos

Si tienes mapa de Google, YouTube o formularios externos, cárgalos solo cuando el usuario baje a esa sección.

12. Optimizar fuentes

Si usas Google Fonts, no cargues demasiadas variantes.

Malo:

Roboto 100, 200, 300, 400, 500, 600, 700, 800, 900
Montserrat 100, 300, 400, 500, 700, 900

Bueno:

Una sola familia
Dos o tres pesos máximo: 400, 600, 700

En el <head> puedes usar:

<link rel="preconnect" href="https://fonts.googleapis.com">
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>

Mejor todavía: alojar las fuentes localmente.

13. Comprimir CSS y JS

Si estás usando un proyecto React, Vite, Next.js o similar, asegúrate de compilar en modo producción.

Para Vite:

npm run build

Para Next.js:

npm run build
npm start

No subas una versión de desarrollo.
